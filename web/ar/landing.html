الفجوة بين أداة الفحص وحاسبة التكلفة

أدوات الفحص السياسي مثل kube-linter وPolaris تتجاهل التكلفة. أدوات التكلفة مثل Infracost تحلّل Terraform، لا ملفات Kubernetes الخام. تجمع Cubzi بين الاثنين، قبل النشر، على ملف الـ YAML الفعلي الذي ستطبّقه.

تقدير التكلفة الشهرية

يقرأ طلبات CPU/memory وعدد النسخ، ويسعّرها مقابل AWS أو GCP أو Azure — تقدير موسوم بوضوح، لا فاتورة.

⚙️

CLI + GitHub Action

شغّله محلياً، أو اربطه بـ CI لإيقاف أي نتيجة CRITICAL، أو احصل على التقرير كاملاً كتعليق تلقائي على الـ PR.

عيّنة مما تكتشفه

أربع فحوصات CRITICAL، وست فحوصات WARNING، وثلاث فحوصات INFO — كل قاعدة تأتي مع الحل الدقيق.

  • CRIT الحاوية قد تعمل بصلاحية root
  • CRIT حاوية privileged
  • CRIT سر (Secret) مكتوب مباشرة في متغير بيئة
  • CRIT تفعيل hostNetwork / hostPID / hostIPC
  • WARN غياب طلبات/حدود cpu أو memory
  • WARN غياب فحوصات liveness/readiness
  • WARN لا يوجد PodDisruptionBudget لأحمال العمل متعددة النسخ
  • WARN وسم الصورة غير مثبّت (latest)
  • WARN لا يوجد NetworkPolicy في الـ namespace
  • WARN الـ Deployment بلا عدد نسخ محدد

آلية العمل

لا عميل يُثبَّت على الكلاستر. المُدخل ملف YAML، والمُخرج تقرير.

الصق الملف أو أشر إليه

استخدم أداة الويب، أو شغّل الـ CLI على ملف أو مجلد كامل.

احصل على تقرير

كل مخالفة مع درجة خطورتها، والمورد الذي تخصه، وطريقة إصلاحها — إضافة لنطاق تكلفة شهري.

اربطه بخط الأنابيب (Pipeline)

يخرج الـ CLI بخطأ عند أي نتيجة CRITICAL؛ ويعلّق GitHub Action بالتقرير على الـ PR.

أضفه إلى CI

يبني GitHub Action الـ CLI ويشغّله، ثم ينشر (ويحدّث) تعليقاً واحداً على الـ PR بالتقرير الكامل.

- uses: Mehrshadshaabani/kubzimanifest@v1
  with:
    path: ./manifests
    cloud: aws
