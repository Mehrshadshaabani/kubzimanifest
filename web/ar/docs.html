توثيق API

كل ما تفعله أداة الويب متاح كواجهة HTTP عادية — نفس القواعد، نفس مقدّر التكلفة، نفس الحد الشهري لكل خطة.

البدء السريع

  1. سجّل الدخول عبر Google أو GitHub.
  2. افتح الأداة، اضغط مفاتيح API في الشريط العلوي، وأنشئ واحداً. يُعرض مرة واحدة فقط — انسخه في مكان آمن.
  3. أرسله كـ Authorization: Bearer <your key> مع أي طلب أدناه.
لست بحاجة لحساب أو مفتاح لتجربة POST /v1/lint إطلاقاً — يعمل بشكل مجهول أيضاً، لكن بلا سجل محفوظ وتحت حد معدل طلبات بسيط لكل IP بدلاً من حد خطتك الشهري.

كيفية استخدام هذا التوثيق

الشريط الجانبي ينقلك إلى كل قسم. يعرض كل صندوق نقطة نهاية طريقة HTTP والمسار، وما إذا كانت المصادقة مطلوبة، وجسم الطلب (إن وُجد)، ومثال curl قابل للتشغيل مباشرة في الطرفية — فقط استبدل مفتاحك الخاص. أجسام الاستجابة المعروضة أمثلة حقيقية مُختصرة، لا مخططات مجردة.

الحقلالنوعالافتراضيملاحظات

cloudنصawsaws أو gcp أو azure
saveمنطقيfalseحفظ التقرير — يتطلب مصادقة
 
curl https://cubzi.cloud/v1/lint \
  -H "Authorization: Bearer mflint_xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "manifest": "apiVersion: apps/v1\nkind: Deployment\n...",

    "save": true

CLI وGitHub Action

تفضّل عدم استدعاء الـ API مباشرة؟ الـ CLI يغلّفه محلياً ولا يحتاج مفتاحاً إطلاقاً:

mflint ./manifests --format=table --cloud=aws

ويغلّف GitHub Action (action/action.yml في المستودع) الـ CLI لتعليق التقرير على طلبات الدمج (PRs) — راجع ملف README الخاص بالمستودع للإعداد.
